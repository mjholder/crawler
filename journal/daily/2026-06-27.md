## Goals for this session

## What I worked on

- Initial framing: boss before the end-of-act node on the world map. Refined during
  implementation — the **boss is the act climax and completes normally** (returns to the
  map), and the **end-of-act node** is what loads the next act. The transition is owned by
  that node, not by the boss event.
- Reframed the unreachable terminal `ShrineMapNode`/`ShrineEvent` into an **end-of-act
  town** and built the **act-swap** mechanism:
  - Rename `ShrineMapNode → EndActMapNode`, `ShrineEvent → EndActEvent` (scripts + `.uid` +
    `end_act_event.tscn`, `world_map_node_end_act.tscn`). Kept `ShrinePanel` as the town's
    **Temple** ascension UI.
  - `EndActMapNode.next_act_scene: PackedScene` (empty = final act → victory).
  - `EndActEvent` drives a hub: emits `town_requested`, stays in `RUNNING` while open,
    exposes `ascension_cost()` / `on_travel_onward()`.
  - New `TownPanel` (`scripts/town_panel.gd` + subtree in `game.tscn`): **Temple** +
    **Travel Onward**, with an extensible `Services` container.
  - `gui.gd`: `town_temple_requested`/`town_travel_requested` signals, `show/hide_town_panel`,
    and `swap_world_map(scene)` (detaches old map synchronously so the new one keeps the
    `WorldMap` name → saved node paths stay valid).
  - `game.gd`: `current_act`; town/temple handlers (ascension applied **live**);
    `_on_dungeon_complete` branches on `EndActMapNode → _advance_to_next_act`;
    **VICTORY decoupled from the boss** (`_on_boss_defeated` no longer sets it).
  - Save: `RunSaveData.VERSION → 2` + `current_act`/`active_act_scene_path`; Continue swaps
    to the saved act map before `apply_state_dict`.
  - Maps: act-1 end node → placeholder `world_map_act2.tscn` (standalone copy; a scene
    can't `ext_resource` itself); act-2 copy ends in victory.

## Key decisions made

Shrine → EndAct town; the world map is **swapped** per act; run-ending victory moves from
the boss to the final act's end-act node. Full rationale in [[design.md]].

## Blockers / struggles

- New `class_name`s aren't recognized by headless `godot --check-only` until a
  `godot --import` pass rebuilds the global class cache — first check spuriously reported
  "Could not find type EndActEvent/EndActMapNode/TownPanel". Clean after import.
- `swap_world_map` initially risked Godot auto-renaming the new map (duplicate `WorldMap`
  name while the old node was still queued-free) — fixed by `remove_child` first.
