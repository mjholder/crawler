## What I worked on

Improved the content editor (`tools/content_editor/`) so two fiddly authoring
tasks are done through purpose-built UI instead of raw-JSON textareas / hand-synced
text fields:

- **Subscriptions widget.** `BlessingData.subscriptions` / `StatusData.subscriptions`
  are `StringName → Effect` dicts; they previously fell through to the raw-JSON
  fallback (only `Enums.*`-keyed dicts got `StatDictField`). Added a
  `SubscriptionsField` in `FieldRenderer.tsx` — each row is a signal `<select>` +
  a reused `ResourceRefField` (Effect picker), with add/remove and per-row signal
  dedupe (modeled on `StatDictField`).
- **Widget-override mechanism.** Threaded an `ownerClass` prop through
  `FieldRenderer` and added a `WIDGET_OVERRIDES` registry (`ClassName.propName` →
  widget id) in `fieldVisibility.ts`, mirroring the existing `FIELD_DIR_OVERRIDES`
  pattern. Kept it as plain-string ids to avoid an import cycle with the widgets.
- **Lifecycle-signal export.** `export_schema.gd` now emits a top-level
  `lifecycle_signals` array (read from `game.gd`'s signal list) so the subscription
  dropdown can't drift from the real bus. Flows through the sidecar `/schema`
  endpoint untouched; added `lifecycle_signals?` to both `GameSchema` TS interfaces.
- **Lineage builder.** New `LineageBuilder.tsx` panel rendered above the generic
  form for `PatronSaintData`: `lineage_id` field + three Act tier slots (reusing
  `FieldRenderer` with a synthetic `Resource` prop, dir-scoped to the tiers dir),
  a **create-next-tier** action (creates the tier `.tres`, wires the ref, stamps
  `lineage_id`), and an **apply-id-to-all-tiers** button that writes `lineage_id`
  into each tier file (cross-resource op). `lineage_id`/`tiers` are hidden from the
  generic field list via a new `PatronSaintData` visibility predicate.

## Key decisions made

- Chose **targeted frontend widgets** keyed by `ClassName.propName` over a general
  schema `widget` hint — matches the existing `fieldVisibility.ts` convention and
  keeps UI concerns out of the Godot/schema pipeline.
- **Export** the signal list from Godot rather than hardcoding it in the frontend,
  so the dropdown stays in sync with `game.gd`.
- No `[[architecture.md]]` / `[[design.md]]` change — this is editor tooling, and
  the lifecycle signal bus already existed.

## Blockers / struggles

- None significant. Avoided an import cycle (fieldVisibility ↔ FieldRenderer) by
  registering overrides as widget-id strings rather than components.
