## What I worked on

Designed and implemented the full single-slot save/load system. Players can now start a new run or continue an existing one; the game saves automatically at every event boundary.

**New files:**
- `scripts/save_data/run_save_data.gd` — `RunSaveData extends Resource`; versioned schema with player dict, world map node states, and run-flow fields (game_state, active_world_node_path, event_index, pending_event_configs).
- `scripts/save_manager.gd` — static API (`has_save`, `write`, `read`, `clear`) with no Node and no autoload. `write` serialises PackedScene refs as `resource_path` strings to avoid the non-deterministic dungeon event generation problem (confirmed: `dungeon_map_node.gd` uses `randi()`).

**Modified files:**
- `scripts/combatant.gd` — added `to_status_save_array` / `apply_status_save_array`.
- `scripts/player.gd` — added `to_save_dict` / `apply_save_dict` / `_clear_equipment_nodes`. Also fixed `initialize()` to use `_clear_equipment_nodes` rather than `_inventory.clear()` — prevents duplicate equipment scene children on a second new-game call.
- `scripts/inventory.gd` — added `to_save_dict` / `apply_save_dict`; directly sets dict / array fields and emits the existing change signals so Player's `_on_slot_changed` / `_on_ring_changed` handlers re-run `_setup_equipment` naturally.
- `scripts/world_map.gd` — added `to_state_dict` / `apply_state_dict` / `get_world_map_node`.
- `scripts/gui.gd` — added `continue_requested` signal, `_continue_button` and `_new_run_confirm_dialog` references, `get_world_map()` accessor, `_on_continue_button_pressed`, `_on_new_run_confirmed`. `return_to_main_menu` / `show_main_menu` now toggle the Continue button via `SaveManager.has_save()`.
- `scenes/game.tscn` — added `ContinueButton` to MainMenu; renamed Start → "New Run"; added `NewRunConfirmDialog` (`ConfirmationDialog`); shifted debug button positions.
- `scripts/game.gd` — wired `_gui.continue_requested`; updated `_on_event_complete` (save after rewards, clear on VICTORY before entering victory); added `SaveManager.write` call at end of `_on_dungeon_complete` for the WORLD_MAP boundary save; added `SaveManager.clear` on `_on_player_died` (permadeath) and at top of `_enter_victory`; added `_on_continue_requested` handler.

**Key health-restoration subtlety:** `apply_save_dict` calls `_recalculate_max_health` once from base stats, sets `health = max_health`, then applies inventory (each equip fires `_on_slot_changed → _recalculate_max_health`), then blessings, then statuses (fires `_on_stat_modifiers_changed → _recalculate_max_health`), then a final `_recalculate_max_health` to pick up blessing CON contributions, then pins `health = minf(saved_health, max_health)`. Starting from `health = max_health` ensures the intermediate per-equip delta calculations never clamp health downward.
