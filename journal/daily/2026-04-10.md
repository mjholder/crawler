## Key decisions made

- RestEvent uses a `heal_percent` config value (0.0–1.0) so heal amount is tunable per node — defaults to 1.0 (full heal)
- REST nodes produce a single event, no dungeon depth or random generation — keeps rest simple and distinct from dungeons
- Followed the same signal routing pattern as SkillCheckEvent: event emits signal → game.gd shows UI → UI emits action → game.gd applies effect → UI emits complete → game.gd advances event

## Blockers / struggles

- `$PATH/TO/NODE` syntax throughout the codebase is fragile — any UI layout change requires updating code. Should refactor to `@export var` references so the editor handles re-pathing automatically.
- No clear vision yet for game balance and progression — leveling curves, enemy/weapon scaling, build diversity. How does the player express themselves and expand possibilities over a run? Too early to finalize but struggling to find the direction. Early thinking: classes at character creation, spells, potions, weapon classes could all add options. Current combat is one action per turn — might not be enough for the player to have fun or feel expressive.
