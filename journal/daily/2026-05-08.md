Modified: `enums.gd` (OFFHAND slot), `equipment_data.gd` (spell_cost_multiplier, bonus_prep_slots), `weapon_data.gd` (innate_spells), `player_class_data.gd` (mana/spell fields), `player.gd` (mana resource, full spell roster system, _do_cast, save/load), `game.gd` (unified `_on_action_requested` dispatcher, spell targeting, cast_hit handler, mana restore on node entry), `gui.gd` (mana bar, spell buttons with cost display, show_status), `inventory_panel.gd` (dynamic prep slot UI).

Tested and fixed three post-implementation bugs. See [[design.md]] — Run-state reset pattern for the architectural decision.

- **Health label showed non-zero on death**: `take_damage` let `health` go negative; `update_player_health(-13, 140)` set the label to `-13/140`. Fixed with `health = maxf(health - net_amount, 0.0)` in `player.gd`.
- **Spells degraded each run**: `initialize()` called `_prepared_spells.clear()` but never reset `prep_slots`, so `_recalculate_prep_slots()` returned early (new_size == prep_slots) and `_prepared_spells` stayed at size 0. `prepare_spell(spell, 0)` then hit the `index >= _prepared_spells.size()` guard and bailed. Fixed by adding `prep_slots = 0` in the reset path so the resize always runs.
- **Zero spells after dying and starting a new run**: `_on_player_died` sets `_dungeon_locked = true` via `_exit_event()`. `_enter_game_over()` never calls `_exit_dungeon()`, so the lock persisted through "Main Menu" all the way into the next `player.initialize()`. `_inventory.equip()` returned early on the lock guard — no weapon, no innate Sparks, no prepared spells. Root fix: `_inventory.set_dungeon_locked(false)` in `reset_run_state()`.

Refactored the reset path to address the structural issue: extracted `Player.reset_run_state()` (owns all per-run teardown including the dungeon lock) and `Game._reset_run_state()` (clears event/targeting/round state, frees stale enemy bars). Both `initialize()` and `apply_save_dict()` now call `reset_run_state()` first; both game entry points (`_on_character_created`, `_on_continue_requested`) call `_reset_run_state()` first. Verified: die→restart (3 cycles), continue, class change all load correctly.
