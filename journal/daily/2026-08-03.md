## What I worked on

Implemented equipment **riders** — binary, rarity-gated behavior, the non-numeric counterpart to
`TagData`. New polymorphic resource family (`scripts/`): `rider_data.gd` (base: `rider_name`,
`description`, `min_rarity` = RARE), `stack_bonus_rider.gd` (`bonus_stacks`), `innate_spell_rider.gd`
(`spell: SpellData`).

`scripts/item_instance.gd` gained a `riders` array composed like `tags`, with the **rarity gate in
one place** — `effective_riders()` returns only riders whose `min_rarity <= rarity`; `stack_bonus()`
and `granted_innate_spells()` read only through it. `add_rider()` mutation + `to_dict`/`from_dict`
serialize rider resource-paths (legacy saves with no `"riders"` key still load).

Two integration seams:
- **Stack rider** — `Player.weapon_context_for` sets `ctx["bonus_stacks"] = inst.stack_bonus()`;
  `scripts/status_effect.gd` folds it in *before* the crit multiply (`int((stacks + bonus) * crit_mult)`),
  so a crit doubles `(base + bonus)` together — the interaction the idea doc calls out.
- **Innate-spell rider** — `Player._build_hand_actions` registers `granted_innate_spells()` into
  `_hand_spells[hand]` (where `_do_cast` resolves), bypassing prep slots with no repertoire changes.

Authored `resources/riders/venomous.tres` (StackBonusRider) and `resources/riders/sparkbound.tres`
(InnateSpellRider → Sparks). Added the three rider scripts to `tools/content_editor/godot/export_schema.gd`
allowlist and regenerated `schema.json` (39 classes).

## Key decisions made

- Riders modeled as a **polymorphic family** (like the Effect family), not a single enum-kind bag —
  the two riders hook different systems and share no numeric payload.
- **Rarity gate enforced at composition** (`effective_riders`), one place, default floor RARE.
- Stack bonus rides the existing weapon **context dict** rather than new plumbing through every
  `effect.apply` call site — minimal, and the crit interaction falls out for free.

## Blockers / struggles

- `--check-only --script` on a single file spuriously fails on cross-`class_name` refs (global class
  cache not loaded in isolated mode); had to `--import` the project first so the registry populated.
- The `crawler-content` MCP caches `schema.json` at sidecar startup, so `write_resource` rejected the
  new rider classes even after `make schema`. Wrote the two `.tres` by hand instead and validated via
  `make verify`. (Restarting the sidecar would refresh its cache for future rider authoring.)
