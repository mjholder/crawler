## What I worked on

- Hand-built the InventoryPanel in `game.tscn`. Equipment slots (`HeadEquipment`, `TorsoEquipment`, `HandsEquipment`, `LegsEquipment`, `FeetEquipment`, `WeaponEquipment`), ring slots (`RingEquipment1/2`), and 15 pre-placed bag buttons (`InventorySlot` … `InventorySlot15`) are all editor nodes now. Discovered that `SIZE_SHRINK_CENTER` on the `BagGrid` GridContainer horizontally centers the 5-column grid inside its parent VBox.

- Rewrote `inventory_panel.gd` to reference the pre-placed scene nodes instead of creating buttons with `Button.new()`. `_ready()` collects node refs via `_collect_node_refs()` (walks `_SLOT_CONTAINER_NAMES` / `_RING_CONTAINER_NAMES` arrays and `_bag_grid.get_children()`) and connects all signals once via `_connect_buttons()`. `setup(inventory)` just stores the inventory and refreshes. `_refresh_bag()` fills/clears the 15 fixed slots in-place — no `queue_free`/`add_child` on refresh. All belt code removed from `inventory_panel.gd`; added `unequip_belt_slot(index)` thin helper for GUI routing.

- Changed `max_bag_size` from 20 to 15 in `inventory.gd` to match the fixed-slot UI. Existing `add_to_bag` cap enforces it automatically.

- Redesigned consumable belt behavior. `ConsumableBeltUI` signal renamed `consumable_use_requested` → `consumable_pressed` — the component is now routing-agnostic. `gui.gd` routes in `_on_consumable_belt_pressed`: if `InventoryPanel` is visible, calls `_inventory_panel.unequip_belt_slot(index)`; otherwise emits `consumable_use_requested` up to `game.gd` as before.

- Refactored the combat HUD into a persistent event HUD. `show_combat_hud` → `show_event_hud` (defaults to sheathed); `hide_combat_hud` → `hide_event_hud`. New `set_sheathed(bool)` disables/enables the `AttackButton`. `game.gd` now calls `show_event_hud()` at the top of `_enter_event()` and `hide_event_hud()` in `_enter_world_map()`. `combat_event.gd`'s `_on_enter` calls `set_sheathed(false)` and `_on_exit` calls `set_sheathed(true)`. All other events run with HUD visible but sheathed, so consumables remain reachable (e.g. agility potion before a skill check).

- Fixed consumable belt equip/unequip. Root cause: the belt node lived inside `CombatHUD` which is hidden outside combat, so management mode buttons were invisible/unclickable on the world map. Fixed by moving `ConsumableBelt` and `ConsumableButton` (template) from `GUI/CombatHUD/ActionMenu` to direct children of `GUI`. Updated `gui.gd` to manage belt visibility explicitly: `show_event_hud` shows the belt, `hide_event_hud` hides it only if inventory is closed, `toggle_inventory` shows/hides based on inventory state. Also fixed a secondary bug where equipping a consumable to a full belt silently dropped the item; now returns it to the bag if `equip_consumable` returns false.

- Added `allows_inventory: bool = false` to the `Event` base class as an opt-in flag for future events (e.g. Sanctuary) that should unlock inventory management mid-dungeon. `_enter_event` unlocks if the flag is set and we're in a dungeon; `_exit_event` re-locks if still in a dungeon. Top-level dungeon enter/exit lock calls are unchanged.

## Key decisions made

- Belt routing lives in `gui.gd`, not `ConsumableBeltUI`. The component stays ignorant of context; the router reads `_inventory_panel.visible`. Keeps ConsumableBeltUI reusable.
- `show_event_hud()` always sets sheathed=true on entry. Combat un-sheathes immediately after via `set_sheathed(false)` in `_on_enter`. Other events never call unsheathe.
- `hide_event_hud()` placed in `_enter_world_map()` (not `_exit_event()`) to avoid a flicker hide/show between chained dungeon events.
- `max_bag_size` is an `@export` — left as a tunable value for bag-expansion upgrades later.
- `ConsumableBelt` node lives at `GUI` level, not inside `CombatHUD`. Visibility managed explicitly so it appears both during events and when the inventory panel is open outside combat.
- `allows_inventory` is an `@export` on the `Event` base class (default false). Wiring Sanctuary later is just flipping the flag in the inspector — no code changes needed.
