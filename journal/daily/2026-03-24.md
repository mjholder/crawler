## Key decisions made

- Dialogue is a UI subsystem, not an Event — doesn't go through the event phase machine
- Consequences fire on **node load**, not on choice selection — choices are pure routing
- Node IDs encode the path of choice indices taken to reach them — no explicit `next` pointers needed in JSON
- `DialogueConsequences` is a standalone class; methods on it are the consequence types; new consequence = new method
- Events trigger dialogue by emitting `dialogue_requested(data)` — game.gd handles the rest, keeping events GUI-agnostic
- `DIALOGUE` added to `Enums.TurnState`; game.gd saves pre-dialogue state and restores it on close
