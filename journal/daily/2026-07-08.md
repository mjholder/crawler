## Goals for this session

- [x] Lay the groundwork for the upcoming status-effect wave: clear combat-inflicted statuses when a fight ends, without stripping run-permanent ones.

## What I worked on

Implemented the "status effects clear at combat end" groundwork from [[ideas.md]] (2026-07-08).

- `scripts/status_data.gd` — added `enum Persistence { COMBAT, PERSISTENT }` and
  `persistence: Persistence = Persistence.COMBAT`. Default keeps all 7 existing status `.tres`
  (poison, bleed, burn, stun, regen, …) correct with no content migration.
- `scripts/combatant.gd` — new `clear_combat_statuses()`: sweeps `COMBAT`-persistence instances
  from `_active_statuses`, emits `status_expired` per removal (HUD row clears), recalcs stats once.
  Deliberately does **not** fire `on_expire` (forced clear ≠ natural expiry).
- `scripts/combat_event.gd` — call `game.player.clear_combat_statuses()` in `_on_exit()`, beside
  the existing enemy-health-bar teardown. `_on_exit` is the single choke point all combat exits
  (victory via `event_complete`, death via `_on_player_died`) funnel through, so one line covers
  every exit route. Enemies need no sweep — freed with the event.
- Regenerated `tools/content_editor/schema.json` (`make schema`); `persistence` surfaced as an
  inline enum property automatically. `make verify` round-trip: 121 passed / 0 failed.
- Docs: new [[design.md]] entry "Combat-inflicted statuses clear at combat end"; updated the
  Effect System v2 field list to note `duration: -1` no longer implies run-permanence;
  [[ideas.md]] entry marked `partially done`.

## Key decisions made

- Field named `persistence: { COMBAT, PERSISTENT }`, not the idea's `source: { COMBAT, EQUIPMENT }`
  — avoids the `StatusInstance.source: Node` collision and correctly covers background/blessing
  sources. See [[design.md]].
- Persistence kept independent of `duration` — a future Bleed is `duration: -1` (never ticks) yet
  combat-sourced and must clear.
- `on_expire` intentionally not fired on the combat-end sweep (mirrors the other full-clear paths).

## Blockers / struggles

  confirmed all exit routes pass through `game._exit_event`.
