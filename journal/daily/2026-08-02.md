## What I worked on

**`ActionData` base (DRY).** Extracted `scripts/action_data.gd` — `class_name ActionData extends
Resource` — holding the shared carrier both actions had drifted into duplicating: `display_name`,
`description`, `target_mode` (+ the `TargetMode` enum, moved here from `AttackData`), `cooldown`,
`effects`, `icon`, `sound`. `AttackData` and `SpellData` now `extends ActionData` and keep only their
one anatomy knob (`power_coefficient`; `power` + `mana_cost`).

- Content: renamed `attack_name`/`spell_name` → `display_name` (25 `.tres`) and `cast_sfx` → `sound`
  (no `.tres` actually carried a `cast_sfx` value, so that was schema-only).
- Call sites: `AttackData.TargetMode.*` → `ActionData.TargetMode.*`; the attack-vs-spell name
  branches in `gui.gd` / `game.gd` / `player.gd` / `inventory_panel.gd` collapse to one
  `.display_name` path. `attack_preview.gd` still needs the two context branches (weapon vs spell
  context builders differ) but keys off the subclasses as before.
- Fixed the content-editor schema exporter (`tools/content_editor/godot/export_schema.gd`): its
  `RESOURCE_SCRIPTS`/`ENUM_SCRIPTS` allowlist still named the renamed `attack_coeff_buff_effect.gd`
  and didn't list the new `action_data.gd`, so `ActionData` / `PowerBuffEffect` / the `TargetMode`
  enum were silently dropped from `schema.json`. Now 36 classes / 15 enums.

**`power` is now fully buffable.** Direct answer to the design question: today `power` was only
composed *additively at the item layer* (smithing + tag `power_delta`) — no flat additive buff, no
multiplicative buff. The multiplicative half already existed as `coeff` (it multiplies `power` and is
even shown to the player as *"×N Power"*), so DRY said reuse it, not build a parallel mult pool. The
one genuinely missing lever — a **flat additive power buff** (distinct from `coefficient_add`, which
adds to the *coefficient* = % of power) — was added:

- `StatusData.power_add` (flat bonus power while active).
- `Combatant.get_power_add()` (Σ across active statuses), mirroring `get_attack_coeff_add()`.
- `Player._weapon_context_from` / `spell_context_for` fold `get_power_add()` into the injected
  `power` var — so the `.tres` `damage_expression` strings stay literally `power * coeff + scale *
  scaling` (no content rewrites), and the buff reaches **both** attacks and casts.
- `AttackCoeffBuffEffect` → generalized to `PowerBuffEffect` (`Mode { POWER_ADD, COEFF_ADD,
  COEFF_MULT }`). Safe rename — no `.tres` referenced it.

Effective term: `(power + Σ power_add) * coeff + scale * scaling`, exactly the shape requested.

## Key decisions made

- **Reuse `coeff` as the multiplicative power lever** rather than a parallel `power_mult` pool — DRY,
  and `coeff` is already surfaced to the player as a "Power" buff.
- **Flat power buff applies to spells too.** The uniform term carries the buff to casts. This is a
  temporary combat buff, not SPI scaling, so it doesn't violate [[ideas/mana-as-capacity]]'s "SPI
  doesn't scale spell damage" — but it is a mild tension worth remembering if caster power is ever
  meant to be *fully* content-only.
