## What I worked on

- Fixed Skeleton Lord health bar showing empty during boss fight (`scripts/skeleton_lord.gd`) — Godot's default script boilerplate had overridden `_ready()` with `pass` without calling `super._ready()`, breaking the `_on_ready()` hook chain and leaving `health` uninitialized at 0.0
- Removed DEFENSE from level-up stat allocation options (`scripts/level_up_panel.gd`) — skipped in both `_rebuild_stat_rows()` and `_refresh()`
- Updated `resources/events/combat/example.json` from flat enemy list to two-wave format (wave 1: 1 skeleton, wave 2: 2 skeletons) — waves are supported natively by `CombatEvent`, not just `BossEvent`
- Moved rewards off the event level for both `DialogueEvent` and `SkillCheckEvent` — dialogue rewards now live on terminal nodes in the tree JSON (`rewards` field alongside `choices: []`), and skill-check rewards split into `rewards_on_success` / `rewards_on_failure`. `DialoguePanel.dialogue_complete` now carries `terminal_node_id` so `DialogueEvent` can look up the path-end reward; `SkillCheckEvent._on_resolution()` picks the outcome-specific dict at its first line. `game._apply_rewards()` is untouched — still reads `current_event.rewards`. No event-level fallback; paths without declared rewards grant nothing. See `design.md` — 2026-04-19.
- Fixed crash when a killing-blow combat victory triggered level-up (`scripts/game.gd:_on_player_turn_ended`) — player's delayed `turn_ended` from the finishing attack animation fired after `current_event` was torn down but before `state` left `PLAYER_TURN`, so `_run_enemy_turns()` cast null to `CombatEvent`. Added a `current_event is CombatEvent` guard; a stale post-combat tick is now ignored.
- Added a default post-combat "The battle is over." dialogue so wins don't snap straight into the next event (`resources/dialogue/post_combat_default.json`, `scripts/combat_event.gd:_on_resolution`). Loads and emits the dialogue through the existing `dialogue_trigger_fired` path; falls through to `Phase.COMPLETE` if the file is missing. Custom `dialogue_triggers.on_victory` overrides still take precedence — no extra message on top.
