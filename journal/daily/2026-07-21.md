## What I worked on

**LUCK crit chance** — made LCK functional as crit chance for attacks and spells, per
[[ideas/luck-crit-loot-quality]]. Two directions of data flow around the shared damage
pipeline:

- **Forward (crit multiplier):** added `Combatant.roll_crit()` (chance = effective `LUCK`/100,
  linear per the design — no hidden constant) and a `Combatant.CRIT_MULTIPLIER` (2.0). `game.gd`
  rolls once per target in all three effect loops (`_on_player_attack_hit`, `_on_player_cast_hit`,
  `_on_enemy_move_performed`) and threads a `crit_mult` into `Effect.apply(source, target, crit_mult)`.
  So the whole hit doubles together: `DamageEffect` ×damage, and the *stacks applied* by
  `StatusEffect` / `GatedBleedEffect` (Saint of Ambush bleed) / `ChainDamageEffect` (arc + flankers).
  A crit doubles what the hit applies (3 burn → 6), not the per-tick damage — ticks never crit.
- **Backward (crit flag):** `take_damage(...)` gained a trailing `is_crit` arg and the
  `damaged(amount, is_crit)` signal now carries it out to `game.gd` → `gui.gd` → `DamageNumber`.

**Enemy crit capability** — added `@export var luck` (default `0.0`) to `Enemy` and mapped it in
`_get_base_stat`. Existing enemies stay at 0 (never crit); crits can be granted per-enemy later.

**Crit visuals** — added `DamageNumber.Kind.CRIT`: hot gold, a `!` suffix, and a 1.4× font pop so
crits read instantly. GUI spawners pick `CRIT` vs `DAMAGE` off the `is_crit` flag. Both `damaged`
handlers in `game.gd` also push a "Critical hit! … takes N damage." line to the combat log
(alongside the existing dodge/armor lines). The `damaged(amount, is_crit, total_amount)` signal
gained a `total_amount` (the full hit before armor). **Both the crit log line and the floating
damage number now report total damage dealt** (pre-armor), not just the HP that bled through —
armor absorption is still conveyed by the armor bar (enemy) and the gray absorbed number (player,
on a full soak). No double-count: the player's white number doesn't fire on a full absorb, so the
gray number owns that case alone.

**Status model unified on stacks** — off the crit-buff/stun-duration discussion, collapsed the
status system onto one lever. Removed `StatusData.stack_policy` and the `StackPolicy { REFRESH,
STACK, MAX_DURATION }` enum entirely — every status is stack-based now, with cool-down set by the
existing `stack_decays` / `burst_on_turn_start` flags. `Combatant.apply_status` lost its policy
`match`. The four former-REFRESH statuses (`stun`/`regen`/`haste`/`weaken`) became `stack_decays`,
and their appliers grant stacks = old duration (stun 1, others 3) so prior behavior is preserved and
only crits now extend them. `BuffEffect` builds a `stack_decays` status and grants `duration ×
crit_mult` stacks — a crit buff lasts twice as long ("crit buffs"). Logged as a design reversal of
the earlier "strict: no duration doubling" rule (see [[design.md]] — Statuses unify on stacks).

**Bug fix — combat state leaked between fights** — per-action cooldowns (and, defensively,
hand-used flags) survived the end of a combat, so a skill put on cooldown in one fight was
still on cooldown in the next combat and even across world-map nodes. Root cause:
`Player._cooldowns` was only ever seeded on use and decremented one-per-turn in `begin_turn()`;
nothing wiped it when a fight ended. Added `Player.reset_combat_state()` (clears both hands'
cooldown dicts + resets `_mainhand_used`/`_offhand_used`) and call it from `CombatEvent._on_exit()`
alongside the existing `clear_combat_statuses()`. Also clear `_cooldowns` in `reset_run_state()`
so a fresh run never inherits stale cooldowns.

## Outcomes

### Completed
- LUCK-driven crit chance live for attacks **and** spells (shared code path), with distinct gold
  crit numbers + combat-log line, and floating numbers/log reporting total (pre-armor) damage.
- Status system unified on stacks (policies removed); crit = ×2 stacks everywhere, which extends
  decaying stuns/buffs (crit stun = 2 turns, crit buff = 2× duration) while DoTs get a deeper pool.
- Verified headlessly against the real classes/scenes/resources: `roll_crit` linearity (luck 45 →
  ~45.4% over 20k rolls), 2× direct damage, `is_crit` signal round-trip, gold `-N!` render, total-
  vs-net split with armor, and the unified statuses (stun crit 1→2 turns & expires, haste 3→6,
  poison still decays, crit buff 3→6). Full project imports clean.

### Incomplete / deferred
- Loot-quality side of LCK — deliberately out of scope (out-of-combat, math deferred).
- Crit multiplier / LCK-slope tuning stays provisional. Current class luck values (40–55) predate
  the attribute rework, so crit rate sits ~40–55% until [[ideas/attribute-distribution-leveling]]
  lands and luck baselines drop — expected, not a bug (kept the pure LCK/100 slope per design).

## Key decisions made
