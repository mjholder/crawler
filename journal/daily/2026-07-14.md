## What I worked on

Audited status-effect and damage-effect coverage to identify what's fully wired vs. plumbing-only vs. still an idea.

Then authored content to exercise the "ready" and "no-code" effects: **four new classes**, each
delivering a backlog effect via a weapon or spell.

- **Templar** — plate warrior with the *Warmace* (`grants_casting`). *Skull Bash* applies **Stun**;
  *Lay on Hands* (spell) applies **Regen** (+ small immediate heal).
- **Duelist** — *Rapier* skirmisher. *Lunge* carries a nonzero `pierce_expression` (**Pierce**);
  *Rend* uses the new `apply_bleed.tres` (`GatedBleedEffect`) to apply **Bleed** only when it draws blood.
- **Hexer** — *Hex Rod* caster. *Enfeeble* (spell) applies the new **Weaken** status (−10 STR/−10 SPI);
  *Wither* is a filler damage spell. Innate *Sparks* cantrip like the mage staffs.
- **Winddancer** — *Spirit Fists* martial artist. *Windstep* is a SELF weapon-attack applying the new
  **Haste** status (+30 AGI / 3t — the sustained form of Flicker).

New leaf resources: `weaken.tres`, `haste.tres` (StatusData, with real icons from the two spare
status-sheet cells at 192,0 / 224,0); `apply_bleed/stun/regen/weaken/haste.tres` wrappers; seven
attacks; three spells; four weapons. Authored bottom-up via the crawler-content MCP tools + raw
`.tres` for anything with AtlasTexture/SpriteFrames sub-resources (the MCP parser drops those, and
its inline-effect serializer is buggy — hand-wrote the inline `DamageEffect` attacks like `immolate`).

## Outcomes

### Completed
- Confirmed burn burst works in-game: health bar steps 3→2→1, then enemy acts.
- Authored four new classes (Templar, Duelist, Hexer, Winddancer) exercising Stun, Regen, Pierce,
  Bleed, Weaken, and Haste. All new resources load clean under `godot --headless` and each class
  resolves its weapon + full 6-piece armor loadout; MCP lint clean.
- Switched the character-creation wizard to **auto-discover classes**. `scenes/game.tscn` had a
  hard-coded `available_classes` list on `CharacterCreationPanel` (warrior/mage/assassin/pyromancer)
  that suppressed the panel's directory-scan fallback, so the four new classes never appeared.
  Removed the explicit list (and the nine orphaned `ext_resource` class/script refs); the panel now
  runs `_load_tres_from_directory("res://resources/classes/")` and picks up all 8 `.tres`. Dropping
  a new class file into `resources/classes/` now surfaces it automatically — no more `game.tscn` edit.

### Incomplete / deferred
- Full effect backlog itemised below — next session will author spells and content to exercise them.

## Effect implementation backlog

### Ready to use — just need a spell/attack referencing them

| Effect | What exists | What's missing |
|---|---|---|
| **Stun** | `stun.tres` (`prevents_action`), code in `player.gd` / `enemy.gd` / `game.gd` | Any spell or attack that applies it |
| **Regen** | `regen.tres` (REFRESH, heals 5/turn), code handles it | Any spell or item that applies it |
| **Pierce** | `pierce_expression` on all DamageEffect subclasses, `_apply_defense` on both combatants | Any attack/spell with a nonzero `pierce_expression` value |
| **Bleed** | `bleed.tres` (STACK, 2 dmg/turn ×4), `GatedBleedEffect` code | An `apply_bleed.tres` wrapper (`GatedBleedEffect` + ref to `bleed.tres`), then any attack using it |

### Need a new .tres authored (no code required)

| Effect | Mechanic |
|---|---|
| **Weaken** | STR/SPI debuff via `stat_modifiers` |
| **Haste** | AGI buff via `stat_modifiers` (sustained form of Flicker) |

| Effect | What's missing |

| **Barrier / Shield** | Flat absorb pool separate from armor (can't express as `stat_modifier`) |
| **Mark** | Proc hook for "next hit deals bonus damage / auto-crits" |
