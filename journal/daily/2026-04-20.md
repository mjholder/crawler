## What I worked on

- Designed the consumables system end-to-end: new `ConsumableData extends EquipmentData` (single-use, four effect types: `HEAL_FLAT`, `HEAL_PERCENT`, `DAMAGE_ALL`, `STAT_BUFF`); a variable-size `_consumable_belt` on `Inventory` with index-based slots (mirrors the ring pattern, separate from the bag); activation dispatched via a new `game.gd._on_consumable_use_requested(index)` that bypasses `execute_action()` so the turn does not end; buff tracking on Player with `_active_buffs` ticked once per player turn just before `turn_ended.emit()`; a `ConsumableBelt` HBoxContainer inside `CombatHUD/ActionMenu` rebuilt from `Inventory` signals.
- Captured the design across three docs — **no code changes this session**:
  - `journal/detailed/character.md` — `ConsumableData`, Inventory belt API (`equip_consumable` / `equip_consumable_at` / `consume` / `set_belt_size` + signals), Player buff tracking, `PlayerClassData.starting_consumable_slots` and `starting_consumables`, new "Consumable Use Dispatch" section, extended Open Questions.

## Key decisions made

- Consumables dispatch outside the action registry, preserving the "`execute_action()` is the single source of `turn_ended`" invariant. See `journal/design.md` — 2026-04-20.
- Consumables are single-use; multi-charge / stacking deferred. Belt size is variable per class with a `set_belt_size()` helper; growth mechanics deferred to `ideas.md`.
- `DAMAGE_ALL` effects no-op outside combat rather than being gated by a `combat_only` flag; revisit if it becomes confusing in playtest.
