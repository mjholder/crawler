## What I worked on

Built the **combat log message feed** — the narrative text banner (dodges, status apply/expire, deaths), separate from floating damage numbers.

- Extracted the pre-authored `CombatMessageFloat` float-up-and-fade animation + its `Label` out of `game.tscn` into a new reusable **`scenes/combat_message.tscn`** (`scripts/combat_message.gd`, `class_name CombatMessage`): `setup(text)`, autoplay on `_ready`, `queue_free()` on `animation_finished`. Made its `LabelSettings` `resource_local_to_scene` so multiple simultaneous messages don't share (and fight over) one `font_color`.
- Turned the existing `GUI/CombatHUD/CombatLog` node into a spawner — new **`scripts/combat_log.gd`** (`class_name CombatLog`): `push(text)` + staggered `_drain()` (`max_queued` cap) instances one message per line so a burst reads as a rising stream rather than clobbering. `clear()` on combat start/end.
- Pacing (`_gap_for`) prefers a named `advance_marker` read off the `CombatMessageFloat` timeline (`Animation.get_marker_time`, Godot 4.3+) so spacing tracks the animation, falling back to the `spawn_gap` export otherwise. - Fixed the broken hook in `gui.gd` (`_combat_log` was typed `RichTextLabel` on a `Control`, and `log_message` called `append_text`). Now `log_message → _combat_log.push`, `show_event_hud → clear()`.

Then built the **floating damage numbers** (the deferred other half of combat feedback), mirroring the combat-log spawn-per-message shape.

- Fleshed out the stub `scripts/damage_number.gd` into `class_name DamageNumber`: `Kind` enum (`DAMAGE`/`HEAL`; `CRIT` left as a TODO until a crit flag exists), `setup(amount, kind)` sets text (`-N` white / `+N` green), and an arc `Tween` (`tween_method` closed-form parabola: symmetric hump + net downward drag → pops up, curves, falls below spawn). Self-frees on the fade `animation_finished`.
- Per-number **randomized ranges** — `rise_range`/`fall_range`/`drift_range`/`duration_range` exports, each rolled per instance (drift direction follows the sign of `drift_range`, default left→right) so a burst fans out instead of tracing one path.
- `scenes/damage_number.tscn`: made `LabelSettings` `resource_local_to_scene` (same reason as `CombatMessage` — independent hue/alpha) and retargeted the RESET+`fade` tracks from `DamageNumberLabel:label_settings:font_color` to root `.:modulate:a`, decoupling the fade (alpha) from the per-kind hue so a green heal doesn't get forced back to white.
- Added a `DamageNumbers` overlay `Control` under `GUI/CombatHUD` (parented there, not to the bar, so a number survives the enemy's death mid-flight); wired via an `@onready var _damage_number_layer` on `GUI` (an export NodePath doesn't resolve — the `GUI` node's props apply before its `CombatHUD/DamageNumbers` grandchild exists, so it bound to null; `@onready` matches how every other node ref in `gui.gd` is fetched).
- `gui.gd`: `_spawn_damage_number(bar, amount, kind)` plus `spawn_enemy_damage`/`spawn_player_damage`/`spawn_player_heal`; cleanup in `hide_event_hud`. Hooked in `game.gd` at the three existing bar-update sites (enemy `damaged` lambda, `_on_player_damaged`, `_on_player_healed`).
- Fine-tuning pass: made the arch always go **left→right** (drift now takes the sign of `drift_range` directly instead of a random flip).
- **Hand-placed spawn markers.** Numbers now launch from author-placed `Control` markers: enemies from a `DamageNumberSpawnpoint` child of the health-bar scene (via `_bar_origin`, falling back to the bar's top-center); the player from `PlayerDamageSpawnpoint` (damage + heal) and mana casts from `SpellSpendNumber`, both fixed points under `CombatHUD` (via `@onready` refs). Refactored the spawner to a point-based `_spawn_at(origin, amount, kind)` + `_marker_center`. Restored my `DamageNumbers` node to a full-screen container (it had been repurposed as a marker) and added the dedicated `PlayerDamageSpawnpoint` in its place.
- **Mana-cost numbers.** New `DamageNumber.Kind.MANA` (blue `-N`); hooked `game._on_player_mana_spent` → `GUI.spawn_player_mana_cost` so a spell's mana spend floats up from the mana marker.
- **Armor-vs-health damage color.** `player.take_damage` returns before `damaged.emit` when the armor buffer soaks the whole hit (no HP loss → no number), so a well-armored player saw nothing. Now **one number per hit, colored by outcome**: added `DamageNumber.Kind.ARMOR` (steel/gray `-N`), added a `fully_absorbed: bool` to the `armor_absorbed` signal (computed from `roundf(net_amount) <= 0.0`), and `game._on_player_armor_absorbed` spawns the gray number *only* when fully absorbed. A partial hit shows just the white HP number (from `damaged`), so the two never stack. All player numbers launch from `PlayerDamageSpawnpoint`.

## Key decisions made

- **Spawn-per-message, not a reused label + queue.** Each event gets its own self-freeing `CombatMessage` instance, staggered ~0.2s, so quick-succession events form a readable rising column instead of overwriting one label. (User's call.)
- **Suppress the combat-end status clear** from the log via a `Combatant` flag — natural mid-fight expiry and the forced end-of-fight clear both emit `status_expired`, indistinguishable at the signal otherwise.

See [[design.md]] — Combat log = spawn-per-message floating instances.
