Then built **per-action cooldowns** — the first action-economy lever beyond "one action per hand per turn" + mana. Attacks were free to spam every turn, so there was no reason to rotate actions; cooldowns force variety.

- New `@export var cooldown: int = 0` on both `AttackData` and `SpellData` (defaults to 0 = no cooldown, so all 145 existing resources are unaffected). Semantics: on use, remaining is seeded to `cooldown`; it decrements once per player turn in `player.begin_turn()`; usable again `N` turns after the use turn.
- Live state is a lightweight per-hand dict on `Player`: `_cooldowns := { hand: {action_name: turns_remaining} }` — mirrors the `StatusInstance.turns_remaining` countdown pattern but kept out of the status system since a cooldown gates one action, not the whole combatant. New helpers: `_action_base_cooldown`, `get_cooldown_remaining`, `get_hand_cooldowns` (UI snapshot), `_tick_cooldowns`.
- Enforced at the single choke point `Player.execute_action` (gate + seed-on-use) and pre-targeting in `game._on_action_requested` (shows "On cooldown", mirroring the "Not enough mana" refusal).

The button now shows a top-left countdown badge (`CooldownContainer`/`CooldownLabel` in `action.tscn`, mirroring the existing bottom-right mana-cost badge) and dims via `modulate` while cooling down. The disable rule is the one existing `_apply_group_states` expression with `or action.cooldown_remaining > 0` appended — stays fresh because cooldowns only change at rebuild-triggering events (action use, turn start).
- Player-only by design — enemies don't get cooldowns; they follow predetermined combat patterns via `_perform_action` instead. The `cooldown` field lives on the shared `AttackData`/`SpellData` resources but enemy AI never reads it. Ships inert — no player content authored yet.

Confirmed the live MCP `crawler-content` server surfaces `cooldown` on both classes (reads `schema.json` fresh, no restart) and round-trips a non-default value with empty lint.
- Taught the authoring skills to prompt for it: `/create-weapon` (per new attack) and `/create-spell` (Group 2 Mechanics) now ask for a cooldown and emit `cooldown = N` only when > 0.

Tier scheme: **0 = basic filler** (spammable — slash/thrust/holy_strike/lunge/palm_strike/flameburst/stab, plus sparks/magic_missile/wither), **2 = moderate** (cleave, flail, rend, chain_lightning), **3 = heavy** (skull_bash stun, assassinate 3× poison, immolate AoE burn; buffs brace/kindle/windstep/flicker; debuff enfeeble; heals lay_on_hands/mend). ## Key decisions made

- **Spawn-per-message, not a reused label + queue.** Each event gets its own self-freeing `CombatMessage` instance, staggered ~0.2s, so quick-succession events form a readable rising column instead of overwriting one label. (User's call.)
- **Suppress the combat-end status clear** from the log via a `Combatant` flag — natural mid-fight expiry and the forced end-of-fight clear both emit `status_expired`, indistinguishable at the signal otherwise.

- **Cooldowns live on the Player as a per-hand dict, not in the status system.** A status gates the whole combatant and carries lifecycle effects; a cooldown gates a single action and is pure bookkeeping, so it reuses the `turns_remaining` decrement *pattern* without the weight. Cooldown value `N` = usable again `N` player turns after use (so `1` is a no-op given the one-per-hand rule; designers use `>= 2`). Ships inert (all zeros) — the field is a balance lever to author later.
