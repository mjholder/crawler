## What I worked on

- Updated `scripts/inventory_panel.gd` `_refresh_bag()` to create evenly-sized bag buttons in the BagGrid GridContainer
- First attempt calculated button width from `_bag_grid.size.x` divided by columns, but buttons were invisible because grid size is 0 during `setup()` (layout hasn't happened yet)
- Switched to using `SIZE_EXPAND_FILL` flag so the GridContainer itself distributes space equally, plus `clip_text` and `OVERRUN_TRIM_ELLIPSIS` to prevent long item names from pushing columns wider
- Wired up the StatsContainer label (already in the scene) to display all 6 effective stats, updating on equipment changes via the signal chain: `Player.stats_changed` → `game.gd` → `gui.update_player_stats()`
- Added `stats_changed(stats: Dictionary)` signal and `build_stats_dict()` helper to `player.gd`
- Added `_on_player_stats_changed()` routing in `game.gd` and `update_player_stats()` formatting in `gui.gd`

## Key decisions made

- Let GridContainer handle equal width distribution via `SIZE_EXPAND_FILL` rather than manually calculating button sizes — avoids timing issues with container layout
- Stats display follows signal-based architecture: Player emits `stats_changed` with a Dictionary payload, game.gd routes it to GUI — no game objects passed into UI components

## Blockers / struggles

- `_bag_grid.size.x` returns 0 when `_refresh_bag()` is called from `setup()` because Godot hasn't laid out the container yet. Manual size calculation doesn't work at that point.
