## What I worked on

Two content-editor bugs fixed, both touching runtime and editor together.

### Bug 1 — Dialogue nav link broken (`.json` vs `.tres`)

Root cause: `/dialogues` sidecar endpoint listed `.json` files, but `App.navigateToPath` calls `/resolve` which only resolves `.tres` files (greps for `script_class`). Clicking the → arrow silently returned null and did nothing.

Fix: switch `/dialogues` to list `.tres` files (`server.ts`). All event dialogue references in data files now point at `.tres` as well.

Introduced `scripts/dialogue_loader.gd` — a static utility that turns any dialogue path (`.tres` or legacy `.json`) into a dialogue `Dictionary`. Replaced every raw `FileAccess.open` call that loaded dialogue JSON:
- `dialogue_event.gd` — `initialize()`
- `skill_check_event.gd` — `_on_resolution()`
- `combat_event.gd` — `_on_resolution()` (default victory) and `_fire_trigger()`

Migrated the `DEFAULT_VICTORY_DIALOGUE` constant to `.tres` and updated `resources/events/dialogue/example.json` and `resources/events/boss/debug_boss.json` to reference `.tres` dialogue paths.

### Bug 2 — Skill-check threshold was always the stat value

The roll panel hard-coded `roll <= stat_value` with no way to author a different DC.

Fix: added `threshold_expression` field (GDScript expression, same variables as `heal_expression` / `damage_expression`). Empty = default stat-as-DC behavior preserved.

Signal thread: `skill_check_requested(stat, label, threshold_expression)` → `game._on_skill_check_requested` evaluates the expression via `StatExprEval` → `gui.show_skill_check` → `SkillCheckPanel.setup` stores both `_stat_value` (display) and `_threshold` (roll comparison).

Editor: added `threshold_expression` textarea + variable hint to `SkillCheckEventForm.tsx`, added field to `EventEditor.tsx` default template, updated `USER_GUIDE.md`.
