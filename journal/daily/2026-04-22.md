## What I worked on

- Migrated `ConsumableBeltUI` from building raw `Button.new()` slots to duplicating a hand-designed editor node. Added `@export var template_button: Button` to `consumable_belt_ui.gd`; `_rebuild()` now calls `template_button.duplicate()` for each slot, sets `visible = true`, and connects the `pressed` signal per index. Extracted `_apply_slot_state(btn, data)` helper shared by `_rebuild()` and `_on_belt_changed()` to avoid duplicated text/disabled logic. In `game.tscn`, moved `ConsumableButton` from inside `ConsumableBelt` to a sibling under `ActionMenu`, set `visible = false`, and wired the new export via `template_button = NodePath("../ConsumableButton")`. The hand-designed button (136×136, "Bomb" placeholder) is now the live template — style changes in the editor automatically propagate to all runtime slots.

- Wired dungeon lock into `game.gd`: `_enter_dungeon()` now calls `player.get_inventory().set_dungeon_locked(true)` and `_gui.set_dungeon_locked(true)`; `_exit_dungeon()` calls both with `false`. Guard-clauses in `inventory.gd` and the `InventoryPanel` UI lock were already in place from the 4/21 session — this was the missing call-site. Also fixed a crash: `game.gd` was calling `player.inventory` directly, but the field is `_inventory` (private); added `get_inventory()` public getter on `Player`.

- Migrated `LevelUpPanel` from programmatic UI to editor-built scene layout. `scenes/game.tscn` already contained the full hand-built row tree (StrengthContainer … LuckContainer, each with NumberLabel / BonusLabel / PlusButton / MinusButton); `level_up_panel.gd` was still creating rows dynamically under a non-existent `StatsContainer`. Rewrote the script to use `@onready`-style `_build_row_ref()` lookups against the existing scene nodes.

- Added class growth bonus display to the level-up panel. `Player._apply_growth_rates()` now accumulates growth into `pending_growth_bonuses: Dictionary` (in addition to mutating base stats as before). `setup()` snapshots the pre-level-up base as `current_base - growth`; `_refresh()` shows `growth + session_spent` in BonusLabel, coloured green when `growth > 0`. Accumulated across multiple level-ups before the panel opens. Cleared by `clear_pending_growth_bonuses()` on confirm. Added public `get_base_stat()` wrapper on `Player` (was private `_get_base_stat()`).

## Key decisions made

- Lock point is `_enter_dungeon` / `_exit_dungeon` in `game.gd` — the natural boundary already used for game state and event config setup.
