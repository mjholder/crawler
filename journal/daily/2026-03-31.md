## Key decisions made

- Used `_set_phase(Phase.RESOLUTION)` directly in `on_skill_check_complete()` instead of `_advance_phase()` — the base implementation goes RUNNING→RESOLUTION→COMPLETE in one call, which would skip the async dialogue wait. CombatEvent has the same pattern.
- `game.gd` owns the stat lookup: `_on_skill_check_requested()` calls `player.get_effective_stat()` and passes the value to the GUI. The event never touches the player reference.
- `dialogue_requested` signal on `SkillCheckEvent` uses the same name and signature as `DialogueEvent`, so the existing `_on_dialogue_requested()` handler in `game.gd` is reused without changes.
