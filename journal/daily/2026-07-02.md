## What I worked on

Play-tested the enemy pattern system shipped yesterday. Enemy turn structure (pattern
data, cursor sequencing, SELF/PLAYER targeting, effect application) held up in live
play. Iterating on combat feel from the session — see Outcomes below.

Implemented [[ideas.md]] — **Dual-Action Combat (Mainhand / Offhand)**: split the
player turn into two independently-gated action slots, one per hand, and folded
spellcasting into the same hand system via a **focus** capability.

- `Player` now keys actions per hand (`_hand_actions[Hand]`), gated by `_mainhand_used`
  / `_offhand_used`. `execute_action(hand, name)` no longer ends the turn — it marks the
  hand and emits `action_resolved`. Turn ends only via the explicit `end_turn()` (End
  Turn button / stun). `_tick_statuses()` moved into `end_turn()` so statuses tick once
  per turn, not per action.
- A hand's action group is derived in `_rebuild_hand_actions()` from the item it holds:
  its `attacks`, plus the prepared repertoire if the item is a focus (`grants_casting`),
  else a weapon's innate spells; an empty hand falls back to the unarmed `Punch`
  (`resources/equipment/weapons/unarmed_strike.tres`). A two-hander sources the locked
  offhand from its `offhand_attacks`.
- Data model: `attacks` and `grants_casting` promoted to `EquipmentData`;
  `offhand_attacks` added to `WeaponData`. Caster foci `pyre_scepter` / `oak_staff`
  flagged `grants_casting = true`.
- `game.gd` resolves/targets per hand and refreshes a two-group bar on `action_resolved`;
  `gui.gd` builds two button groups + an End Turn button (fallback nodes auto-created if
  the CombatHUD scene doesn't define `MainhandActions` / `OffhandActions` / `EndTurnButton`
  under `ActionMenu` yet).

### Bug fixed (play-test)
- **Mid-turn wave softlock.** Landing a wave's last kill with one hand while the other
  was still free locked the game: `action_resolved` fired into the momentarily-empty
  encounter (enemy dead, next wave not yet spawned — it waits on `await death_finished`)
  and `_on_player_action_resolved`'s no-living-enemy guard bailed without re-enabling the
  bar, which `_confirm_targeting` had disabled. When `_start_next_wave` then spawned the
  new wave, nothing re-granted control — bar + End Turn stayed disabled in `PLAYER_TURN`,
  so enemies couldn't act either. Fix: `game._on_combat_wave_started` re-enables the turn
  (`_refresh_action_bar` + `set_player_turn(true)`) when a **new wave begins** during
  `PLAYER_TURN` and we're not mid-targeting. Keyed to wave start rather than raw enemy
  spawn (`enemy_added`) so a summoner adding minions during the enemy turn never re-grants
  control. The last-wave path is unaffected (it goes to RESOLUTION/dialogue, emitting no
  `wave_started`), so the killing-blow guard still holds there.

## Key decisions made

- **Turn end is explicit only.** Actions never auto-end the turn (even with both hands
  spent); `end_turn()` is the sole terminator. See [[design.md]].
- **Casting is a hand capability granted by a focus** (`grants_casting`), channeling the
  prepared repertoire — no focus, no casting. Reuses WEAPON/OFFHAND slots. See [[design.md]].
- **Two-handers keep both hands** via a supporting `offhand_attacks` action rather than
  forfeiting the offhand.

## Blockers / struggles

- The `_turn_pending` flag conflated "action resolving" with "end the turn"; splitting it
  into `_action_resolving` + explicit `end_turn()` was the load-bearing change everything
  else hung off.
