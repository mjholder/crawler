## Outcomes

### Completed
- First full act-progression playtest completed.
- **Floor events: enums + bitmask tags**. Added `Enums.EventType` (COMBAT/BOSS/DIALOGUE/SKILL_CHECK/REST,
  order matches the old `@export_enum` indices so `.tres` values needed no migration) and a bitmask
  `Enums.FloorTag` (SHORT=1, MEDIUM=2, MIXED=4, DEMO=8). `FloorSlot.event_type` and
  `WeightedEntry.event_type` are now typed `Enums.EventType`; `FloorEventPool` is keyed by the enum
  throughout (dropped the `TYPE_NAMES` string lookup). `DungeonFloorData.tags` and
  `DungeonMapNode.floor_tags` are now `@export_flags("Short:1",…)` ints; `filter_by_tags(mask)` does a
  bitwise AND-match. Migrated the 3 floor `.tres` (`tags = 1/6/8`) and the 4 world-map scene nodes
  (`floor_tags = 1/2`).
- **Content editor `flags` type**. `export_schema.gd` now emits `type:"flags"` + `flag_values` for
  `PROPERTY_HINT_FLAGS`; `PropDescriptor` gained `flag_values` (sidecar + frontend); `FieldRenderer`
  renders a multi-checkbox `FlagsField`. `event_type` needed no editor code change — the existing
  `EnumField` picked up the typed enum after a schema regen. `make schema` clean, `make verify` 103/0.

### Fixed
- **Temple multi-ascend bug**: `EndActEvent` now tracks `_has_ascended` and grants at most
  one tier per node visit. After ascending, re-opening the Temple shows the no-further-ascension
  state. Guard lives in both `game._on_gui_town_temple_requested` (panel display) and
  `_on_gui_shrine_ascend_requested` (the apply path).
- **War axe missing attacks**: confirmed a misconfigured resource — `war_axe.tres` set no
  `attacks` array at all (unlike `battle_axe.tres`). Gave it `slash + cleave + flail`.
  Side note: `chop.tres` is itself broken (`target_mode` all, but no `effects`), so it was
  left off the axe.
- **Boss in random dungeon pool**: every standard floor (`standard_medium`, `standard_short`,
  `scripted_demo`) appended a FIXED boss slot, so any regular `DungeonMapNode` rolling those
  floors spawned a boss. Removed the boss slots from all three floors, and added a guard in
  `FloorEventPool.event_config_for()` — the single choke point all slot resolution funnels
  through — that refuses boss-type wrappers with a warning. Boss fights now come only from
  `BossMapNode`, which loads the boss directly and bypasses the pool.

### Incomplete / deferred
- **Boss fight in dungeon event pool**: boss fight is appearing as a possible random dungeon event — should be reserved for dedicated boss nodes only.

- **Single source of truth for event/floor vocabularies** = enums in `enums.gd`. Floor tags use a
  bitmask (a floor can carry several tags); event types use a plain enum (one per slot). `@export_flags`
  labels carry explicit bit values (`"Short:1"`) so the content-editor checkboxes stay locked to
  `Enums.FloorTag` regardless of label casing. Each tag currently still maps to exactly one floor, so
  tag-based nodes behave like a direct `floor =` ref until more floors share a tag. See [[architecture.md]]
  (floor/event data model diagram updated).
