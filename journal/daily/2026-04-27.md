## What I worked on

- Added `paper_doll_front: Texture2D` and `paper_doll_back: Texture2D` exports to `equipment_data.gd`
- Created `scripts/paper_doll.gd` — a `Control` that stacks `TextureRect` layers for each armor slot, listening to `Inventory.slot_changed` to swap textures reactively
- Wired the paper doll into `inventory_panel.gd` via `get_node_or_null` so it degrades gracefully if the node isn't built yet
- Hand-built the `PaperDollPanel > PaperDoll` node tree in `scenes/game.tscn`: base body layer + per-slot TextureRect layers in back-to-front render order (body → back arm → legs → boots → chest → front arm → helmet)
- Updated all six armor `.tres` files to reference their 160×270 paper-doll sprites
- HANDS (gauntlets) uses two textures: `arms_right.png` on `HandsBackLayer` (behind the chest) and `arms_left.png` on `HandsFrontLayer` (in front)
- Set `texture_filter = NEAREST` on the `PaperDoll` Control to propagate pixel-crisp rendering at 2× scale (Daggerfall aesthetic)
- Expanded all enums in `enums.gd` to one-value-per-line with integer comments, matching the existing `Stat` pattern

## Key decisions made

- Two texture fields on `EquipmentData` (`paper_doll_front` + `paper_doll_back`) rather than a single field or subclass — keeps HANDS' split-arm rendering generic and extends cleanly to future cloaks/shields without special-casing
- Paper doll wired via `InventoryPanel` rather than `gui.gd` — panel owns its children, no new public API needed
- Base body (`man.png`) loaded via `preload` in `_ready()` rather than set in the inspector — one less editor step, and the base body is a fixed property of the feature not an instance variable

## Blockers / struggles

- Godot silently strips unknown resource fields when a `.tres` is opened before the script is reloaded — `leather_chest.tres` lost its texture reference this way. Workaround: reload scripts in Godot before opening `.tres` files after any `EquipmentData` field changes
