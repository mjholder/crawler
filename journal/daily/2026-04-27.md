## Key decisions made

- Two texture fields on `EquipmentData` (`paper_doll_front` + `paper_doll_back`) rather than a single field or subclass — keeps HANDS' split-arm rendering generic and extends cleanly to future cloaks/shields without special-casing
- Paper doll wired via `InventoryPanel` rather than `gui.gd` — panel owns its children, no new public API needed
- Base body (`man.png`) loaded via `preload` in `_ready()` rather than set in the inspector — one less editor step, and the base body is a fixed property of the feature not an instance variable

## Blockers / struggles

- Godot silently strips unknown resource fields when a `.tres` is opened before the script is reloaded — `leather_chest.tres` lost its texture reference this way. Workaround: reload scripts in Godot before opening `.tres` files after any `EquipmentData` field changes

## What I worked on (continued)

### Attack type & targeting system

Built a configurable attack-type and targeting system end-to-end:

**New data model**
- `Effect` (Resource base) with virtual `apply(source, target)` — extensibility hook for any future effect type
- `DamageEffect extends Effect` — `damage_expression: String` evaluated via Godot `Expression` against source stats (`strength * 0.5`, `5`, `strength + agility * 0.3`, etc.)
- `AttackData extends Resource` — `attack_name`, `target_mode` (`SINGLE_ENEMY / ALL_ENEMIES / SELF`), `effects: Array[Resource]`
- `WeaponData` gains `attacks: Array[Resource]` — weapons now declare their full move list
- Battle Axe updated with Slash (SINGLE_ENEMY) and Cleave (ALL_ENEMIES); debug Brace weapon added for SELF-path testing

**Player changes**
- `signal attack(damage)` replaced with `signal attack_performed(attack_data, targets)` — single signal for both weapon animation and effect resolution
- New `signal weapon_attacks_changed(attacks)` emitted on equip/unequip — drives GUI button rebuild
- Action registry unchanged (still zero-arg Callables); targeting payload stashed on Player via `set_pending_attack_payload()` just before `execute_action()`
- `_setup_equipment` / `_teardown_equipment` now iterate `WeaponData.attacks` to register/unregister per-weapon actions; works for weapons with and without a scene
- `_calculate_damage()` removed — formula lives in `DamageEffect`

**Targeting state machine in Game**
- Five-state vars: `_targeting_action`, `_targeting_attack`, `_targeting_candidates`, `_targeting_index`, `_target_indicators`
- `_on_attack_requested(name)`: same button = confirm; different button = cancel + re-enter for new action
- `_confirm_targeting()`: validates targets, sets payload on player, calls `execute_action`
- `_cancel_targeting()`: clears state and hides visuals
- Arrow-key cycling via `_unhandled_input` — Escape cancel consumes event before pause menu
- Vignette overlay (purple ColorRect on CanvasLayer 2) shown for SELF targeting
- `TargetIndicator` — Node2D child with `_draw()` yellow arc ring + opacity pulse tween, reparented to selected enemy

**GUI**
- Static `AttackButton` removed from `game.tscn` and `gui.gd`
- `rebuild_action_buttons(attacks)` dynamically creates one Button per attack with bottom-right anchor stack
- `set_targeting_action(name)` highlights the confirming button (yellow tint); clears on cancel/confirm
- `set_sheathed` updated to iterate `_action_menu` children instead of touching a fixed button ref

**Combat resolution**
- `_on_player_attack_performed(attack_data, targets)` iterates effects × targets — replaces the hardcoded first-living-enemy loop
- `CombatEvent.receive_player_attack` and `player_attack_resolved` removed; `player.attack` connect/disconnect moved to `Game.set_player` lifetime
