## What I worked on

- Reworked **bleed** into its own distinct DoT (was nearly a poison clone: 4-turn
  duration, 2 dmg/stack). New identity: **permanent for the encounter, 1 damage per
  stack per turn, health-damage only, ticks at end of the bearer's turn.** Turned out the
  architecture already supported all of this — `GatedBleedEffect` already gates on HP loss
  (armor-absorbed hits never bleed), statuses already tick at end of turn, `duration = -1`
  is already handled as permanent, and `gui.gd` already renders the stack count on the
  icon. Only `resources/effects/statuses/bleed.tres` was out of sync with the intent.
  Edited two values: `duration` 4 → -1, tick `damage_expression` "2" → "1". Lint clean.
  With 1 dmg/stack the on-icon stack number now *equals* expected damage/turn (legibility).
- Added the **vulnerable** status: bearer takes **+50% attack damage**, but DoT ticks are
  unaffected. The system had no attack-vs-DoT distinction, so I threaded an `is_attack` flag
  through `Player`/`Enemy.take_damage` — effect `.apply()` paths default `true` (attacks),
  the two tick paths (`DamageEffect.apply_tick`, `BurstDamageEffect.apply_tick`) pass
  `false`. The multiplier is data-driven: new `StatusData.incoming_attack_multiplier` (1.0 =
  none, 1.5 = vulnerable, 0.5 = a future ward), summed via product in a new
  `Combatant.get_incoming_attack_multiplier()`, applied before armor so the buffer still
  soaks the enlarged hit. Reusable for any future amplify/ward status.
- **Shield dropped:** `BraceEffect` already is "temp armor added to the buffer, auto-reset
  next round by `refresh_armor()`" — a second shield mechanic would be redundant.
- `vulnerable.tres` stacks its **timer** (poison-style `STACK` + `stack_decays`, base
  `duration` 1) — re-applying adds a turn; with no `on_tick`, stacks affect only the
  countdown, never the flat 1.5× multiplier. Lint clean, field round-trips via MCP.

## Outcomes

- Fixed a DoT-vs-armor bug: tick damage went through `take_damage → _apply_defense`, so a
  bleed/poison tick chipped the armor buffer, which then refilled at round start — the DoT
  never reached HP on an armored enemy. Added a `bypass_armor` flag on `DamageEffect`
  (threaded only through `apply_tick`) and a `bypass_armor` param on
  `Player`/`Enemy.take_damage`; enabled it on the poison and bleed tick sub-resources.
  DoT ticks now hit health directly. Burn left untouched (still armor-affected) — revisit
  if it should bypass too.
- Playtested the bleed/poison-through-armor fix — confirmed working (armored enemy now
  loses HP to bleed each turn).
- Tooling: regenerated `tools/content_editor/schema.json` (`make schema`, Godot headless)
  so the new `DamageEffect.bypass_armor` (bool) is known to the MCP `get_schema` and the
  content editor's field UI. Bool fields already render, so no frontend change. The
  committed schema had also drifted — it was missing `pierce_expression` — now current.
  `make verify` round-trips all 142 `.tres` clean. Note: the long-lived MCP server caches
  the schema at startup, so it needs a restart to serve the updated schema.
