## What I worked on

Rebuilt the enemy health bar as a **Control-based** widget instead of Node2D sprites.
The old `health_bar.tscn` was a `Node2D` scaling `Sprite2D`s (`scale.x = ratio * dim`);
reauthored it as a `Control` root holding `Health`/`Armor` sub-controls (each a
`ProgressBar` + centered `Label`) and a `Statuses` `HBoxContainer` for status icons.
Rewrote `health_bar.gd` to `extends Control` and drive the progress bars/labels directly,
keeping the same public API (`set_max_health`/`set_current_health`/`set_armor`) so callers
didn't churn. The `Armor` sub-control hides itself when `max_armor <= 0`.

Placement still works because the spawn code converts the enemy's world position to screen
pixels (`get_viewport().get_canvas_transform() * enemy.global_position`) — a Control's
`position` lives in those same pixels. Two spawn-path fixes in `gui.gd`
`add_enemy_health_bar`: (1) `add_child` **before** feeding data, since the bar's node refs
are now `@onready` and only resolve once it's in the tree; (2) subtract `size.x * 0.5` to
center the bar over the enemy, since a Control positions by its top-left corner (unlike the
old Node2D origin).

Enemy statuses now render as **real icons** in the bar's `Statuses` HBox via the same
`_make_status_icon` the player strip uses (atlas icon + stack-count overlay + tooltip),
replacing the old bare `Label`. Dropped `add_enemy_status_label` + the `_enemy_status_labels`
dict; `refresh_enemy_statuses` rebuilds the icon strip.

Then fixed a **poison stacking bug**. Poison had two independent counters: `stacks` scaled
per-tick damage but never decreased, while a separate `turns_remaining` (`duration`, default
3) controlled how many times it fired — so poison-3 dealt full `3×stacks` damage three times
(flat), instead of draining. Added an opt-in `stack_decays: bool` on `StatusData`: when true,
each tick consumes one stack and the status expires at 0 stacks, with `turns_remaining` kept
in lockstep so tooltips/expiry stay coherent. Poison now drains **3/2/1** (per-stack damage
`"1"`) and expires. Bleed/burn keep their duration-driven curves (they left `stack_decays`
off).

## Key decisions made

- Enemy health bars are `Control` nodes (not Node2D). World→screen placement via the canvas transform means Control `position` works identically; the payoff is UI-native `ProgressBar`/`theme`/`tooltip`/HBox for statuses.
- DoT decay is per-status, not per-`StackPolicy`: added `StatusData.stack_decays` so poison drains while bleed (sustained) and burn (duration-decay) keep their own curves.
