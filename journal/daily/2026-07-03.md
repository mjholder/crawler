## What I worked on

Scoped out per-hand weapon restrictions — allowing weapons to be flagged as
`MAINHAND_ONLY`, `OFFHAND_ONLY`, or `EITHER`, with an optional separate moveset when
in the offhand — then implemented the whole thing in one pass:

- **Data model:** new `Enums.HandRestriction`; `WeaponData` gains `hand_restriction` and
  `as_offhand_attacks`; `offhand_attacks` renamed `locked_offhand_attacks` (code-only — no
  `.tres` set it).
- **Hand logic:** `_build_hand_actions()` uses `as_offhand_attacks` for a weapon in the offhand,
  falling back to `attacks`.
- **Equip UI:** `InventoryPanel` routes equips by `hand_restriction`; an `EITHER` weapon opens a
  hand-selection interaction mirroring combat targeting (slot-button highlight, `←/→` cycle,
  Space/Enter or click to confirm, Esc to cancel). Bag removal deferred to confirm.
- **Animated offhand weapons:** retired the v1 "mainhand-only animates" limitation. `player.gd`
  wires an OFFHAND `Weapon` node flipped via `scale.x = -1` (mirrors the mainhand animation),
  driven by new `offhand_attack_performed` / `offhand_cast_performed` signals + parallel
  `_offhand_*` in-flight state.
- Cosmetic mirrored `OffhandLayer` on the paper doll.
- Flagged Vorpal Blade `EITHER` with a Stab-only `as_offhand_attacks` for testing.

Decision logged in [[design.md]]. All scripts parse and the project boots headless clean.

**Inventory detail-panel flicker fix:** the item detail panel was calling `.hide()` on
mouse-exit. Hidden children take zero space in an `HBoxContainer`, so the whole inventory row
reflowed on every hover on/off — and when the panel expanded, a button could slide out from
under the cursor, triggering mouse-exit → collapse → button slides back → mouse-enter, an
oscillating flicker loop. Fixed by keeping the panel permanently visible (it already reserves a
fixed 200px via `custom_minimum_size`) and having `_hide_detail()` clear its labels instead of
hiding the node. Dropped the now-unused `_detail_panel` reference.

**Tomes folded into the bag:** the dedicated Tomes section was too niche. `TomeData`
now `extends EquipmentData` (mirroring `ConsumableData`) so tomes are ordinary bag
items — no more `Inventory._tomes`, `tomes_changed`, `add_tome/remove_tome/get_tomes`,
or the dynamic Tomes UI. `InventoryPanel._on_bag_button_pressed` gains a `TomeData`
branch: instead of equipping, it removes the tome from the bag and calls
`player.learn_spell`; the detail panel shows "Teaches: <spell>". Learning stays
dungeon-locked for free (bag removal is). Delivery (`starting_tomes`,
`event.rewards["tomes"]`) now routes to `add_to_bag`, so tomes count toward the
15-slot cap. Save/load folds any legacy `"tomes"` key into the bag. `tome_of_mending.tres`
`gold_value` → base-class `price`. Updated [[architecture.md]] and [[ideas/per-hand-weapon-restriction]].

**Content editor — surfaced the new content in the web UI:** the schema layer
(`schema.json` / `annotations.json`) already carried the dual-hand weapon fields
and the `EnemyMoveData` / `EnemyPatternData` classes (so MCP authoring worked),
but the React editor had no UI for them. Three frontend edits:
- Added **Enemy Patterns** and **Enemy Moves** to `CONTENT_TYPES`
  (`frontend/src/types/schema.ts`) so they get a sidebar list + "+ new" button.
- Made the top-level `ResourceForm` honor `FIELD_VISIBILITY` (previously only
  `InlineResourceEditor` did) so per-class field-hiding predicates apply to files.
- Added a `WeaponData` predicate: `as_offhand_attacks` shows only for `EITHER`
  weapons, `locked_offhand_attacks` only for two-handers.
`make verify` still green (121/121 round-trip).
